# Terraform / IaC Module Conventions

## File layout per module

Every module contains exactly these files:

| File | Purpose |
|---|---|
| `main.tf` | Resource definitions |
| `variables.tf` | Input variables with types and descriptions |
| `outputs.tf` | Output values |
| `versions.tf` | `terraform` block with `required_version` and `required_providers` |
| `README.md` | Generated by `terraform-docs`, kept in sync |

Additional files are acceptable for large modules:
`data.tf` (data sources), `locals.tf` (local values),
`iam.tf` (IAM bindings). Each must be single-purpose.

## Variable conventions

- Every variable has `description` and `type`. No `any`.
- Defaults are set only when a sensible org-wide default
  exists. Environment-specific values come from Terragrunt
  inputs.
- Validation blocks (`validation { … }`) are used for
  variables with constrained domains (e.g., region must be
  `europe-west1` or `europe-north1`).

## Output conventions

- Outputs that other modules consume are marked with
  `description` explaining the consumer.
- Sensitive outputs use `sensitive = true`.

## Versioning

- Shared modules are versioned via Git tags:
  `modules/<name>/v1.0.0`.
- Consumers pin to a specific tag or commit SHA, never to a
  branch.
- Breaking changes bump the major version and are documented
  in the module's `README.md` changelog section.

## Documentation

- `terraform-docs` is configured in `.terraform-docs.yml` at
  the repo root. CI verifies that `README.md` is up to date
  with the current variables/outputs.
